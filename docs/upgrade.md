# RC1またはv0.1.0からv0.2.0へ更新

この手順は`0.2.0-rc.1`（RC1）または`0.1.0`からの手動更新を対象とします。アーカイブは未署名です。[新規導入手順](install-nextcloud.md)と同様に、配布元と独立して入手したチェックサムで照合してください。環境の適合性が確認できない場合は停止します。以下の`occ`はNextcloudルートでWeb実行ユーザーとして実行します。

## 更新前

1. **実行場所：Nextcloudルート。** `php occ status`、`php occ config:app:get nextcloud_gateway installed_version`、`php occ app:list`を実行し、現在の版、状態、アプリ有効状態、対象ユーザーの`allowed_roots`を記録します。版がRC1または0.1.0でなければ、この手順を続けません。
2. 全DAVクライアント、cron、外部writerを止め、進行中の書込みを完了させます。未送信クライアント編集も別途保護します。
3. **実行場所：Nextcloudルート。** `php occ maintenance:mode --on`を実行し、全Webワーカーを排出します。
4. DB、設定、データ、現在の`nextcloud_gateway`コードを同一時点でバックアップし、隔離環境で復元可能であることを確認します。旧コードはWeb公開範囲とアプリ探索パスの外に退避します。
5. 配布アーカイブのチェックサムを検証します。未提供・不一致・未置換の値があれば進みません。未署名のためチェックサム照合のみで真正性が保証されるわけではありません。

## コード置換と更新

**実行場所：** アプリ配置先が見えるシェルで、同じファイルシステム上に一時展開します。`nextcloud_gateway/appinfo/info.xml`を確認し、既存アプリへのoverlayはしません。既存アプリディレクトリを探索パス外へ退避してから新コードを配置し、所有者・権限を確認します。

**実行場所：Nextcloudルート。** Web実行ユーザーとして次を実行します。

```sh
php occ upgrade
php occ config:app:get nextcloud_gateway installed_version
php occ status
```

`--force`は付けません。失敗時は新コードで運用を開始せず、以下の復旧手順へ進みます。成功時は版が`0.2.0`であること、DB状態、従来のアプリ有効状態とユーザー設定を確認します。メンテナンスモードを解除後、合成ファイルで読み書き、SHA ETag、古い条件の412をDAV経由で確認し、問題がない場合にのみwriterを再開します。これらは運用者が実施する確認手順であり、個別環境の結果を保証しません。

## 安全なロールバック

- **機能のみ停止：** writerを停止し、NextcloudルートでWeb実行ユーザーとして`php occ config:app:set nextcloud_gateway experimental_enabled --value=no`を実行します。全ワーカーに反映されたことを確認します。DAVの読み取り確認で本文が保たれ、GatewayヘッダーがなくネイティブETagに戻ったことを確かめてからvalidatorを取り直します。これはデータの巻戻しではありません。
- **更新前の状態へ完全復旧：** writerを停止し、メンテナンスモード下で同一時点のDB・設定・データ・アプリコードを一緒に復元します。整合性を確認するまで書込みを再開しません。
- 更新後のDBに古いアプリコードだけを戻すin-place downgradeは禁止です。復元手順に確信がなければメンテナンスを継続し、管理者の復旧手順に従ってください。
