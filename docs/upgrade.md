# v0.3.0 / v0.3.1-rc.1 から v0.3.1 へ更新・復旧

この手順の対象はv0.3.0またはv0.3.1-rc.1からの手動更新です。未署名アーカイブを[導入手順](install-nextcloud.md#アーカイブ照合と配置)に従い独立入手したチェックサムと照合します。未置換・照合不能・不一致なら中止します。外部ストレージ、暗号化、サブマウントは対象外です。

## 更新前

1. **Nextcloudルート（Dockerならアプリコンテナ内 `/var/www/html`）、Web実行ユーザー：** `php occ status`、`php occ config:app:get nextcloud_gateway installed_version`、`php occ app:list` を実行し状態を記録。版が `0.3.0` または `0.3.1-rc.1` でなければ中止。
2. `php -r 'exit(PHP_INT_SIZE === 8 ? 0 : 1);'` を実行し、64-bit PHPでなければ中止。
3. DAVクライアント、cron、外部writerを停止し、進行中書込みを完了。未送信編集も保護。
4. Nextcloudルートで `php occ maintenance:mode --on`。標準運用の停止手順に従い、全Webワーカーを排出。
5. DB、設定、データ、現在のアプリコードを同一時点でバックアップし復元可能性を確認。旧コードはWeb公開範囲・アプリ探索パスの外へ保管。
6. [新規導入の照合例](install-nextcloud.md#アーカイブ照合と配置)のサイズ・SHA-256検査だけを実施。新規配置や `occ app:enable` の手順は実行しません。

## コード更新と確認

**実行場所：** アプリ配置先が見えるサーバーシェル。同一ファイルシステムの一時領域に展開して `nextcloud_gateway/appinfo/info.xml` を確認。既存コードへoverlayせず、旧ディレクトリを探索パス外へ退避して新コードを配置。所有者・権限を確認します。

**実行場所：** Nextcloudルート、Web実行ユーザー。

```sh
php occ upgrade
php occ config:app:get nextcloud_gateway installed_version
php occ config:app:get nextcloud_gateway scope_mode
php occ status
```

期待する版は `0.3.1`。scopeの動作は更新元から引き継ぎ、自動的に全ユーザーへ拡張しません。キーが未設定なら管理画面で実効動作を確認し、確認だけのために設定を保存しないでください。RC1で保存済みのファイル上限・累積ハッシュ予算は維持されます。未設定時のアプリ既定値はそれぞれ10 GiB、50 GiBで、管理者は各々1〜4294967295整数GiBに設定できます。`config.php` およびユーザーのバイト上限は引き上げません。明示済みファイル上限が10 GiB超なら新しい既定値で実効上限が下がることがあります。

writerを停止したまま `php occ maintenance:mode --off` とし、新コードですべてのWebワーカーを起動します。設定値と合成ファイルへのDAV応答を確認してからwriterを再開します。v0.3.0から更新し、以前のアプリ予算に戻す場合は **管理者設定 → 基本設定 → Warifu** でファイル `50`、累積ハッシュ `1`（GiB）を保存します。v0.3.1-rc.1からの更新では保存済み値を保持し、必要がない限り変更しません。より低い個別・システム設定はそのまま効きます。

## 停止と完全復旧

- **機能停止のみ：** writer停止中に設定画面で `off` を保存し、全ワーカーへの反映を確認。DB・データ・コードを戻す操作ではありません。
- **更新前への完全復旧：** writerを停止し、メンテナンスモード下で同一時点のDB・設定・データ・アプリコードを一緒に復元。整合性確認まで書込みを再開しません。

更新後DBに旧アプリコードだけを戻すin-place downgradeは禁止です。確実に復旧できない場合はメンテナンスモードを維持し、管理者の復旧手順に従ってください。
